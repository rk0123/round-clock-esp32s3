# v3.1.2 发布说明

主题：**充电判定重做** —— 修掉「充电动画消失」和「拔了 USB 还显示充电」，模拟表盘补上流水灯。

> 本版承接 v3.1，包含 v3.1.1 未发布的改动（模拟表盘充电流水灯）。

## 1. 现象：充电动画"没了"，后来又"拔了还显示"

两个症状看着像两个 bug，**其实是同一个病根的两面**：充电判定读错了寄存器。

原来只有一条判据：

```cpp
gBat.charging = gBat.valid && (gBat.ma > 20);   // 电流 > 20mA 就算在充电
```

设备实测（电池长期插着线）：

```
[BAT] valid=1 soc=30% mv=4143 ma=0 charging=0
```

`ma` 一直是 0，于是**充电态永远不成立**，两个表盘都不会进入充电态。
用户看到的就是"充电动画没了"。

**为什么电流是 0？** 因为电池早就充满了，充电 IC 自动停充。而用户恰恰总插着线，
所以这个"充满停充"的工况变成了常态 —— 电流表读 0 是**正确**的，错的是拿它当唯一判据。

v3.1.1 的错误尝试：改用 `BatteryStatus(0x0A)` 的 **DSG 位**（bit0，1 = 放电中）。
这位在这颗芯片上**拔掉 USB 仍然恒为 0**，于是判据永远成立 —— 从"永远不充电"
变成"永远在充电"，就成了第二个症状。

## 2. 真实数据（靠新增的 `CHGH` 采到的）

拔线时 USB-CDC 会跟着断，串口读不到那一刻。为此加了 `CHGH`：每 3 s 记一条，
环形 40 条 ≈ 2 分钟，纯内存不写 NVS。拔掉 → 等半分钟 → 插回 → `CHGH`，
就能对账断电期间到底发生了什么：

| 场景 | 电压 | 电流 | `0x3D` OperationStatus |
|---|---|---|---|
| 插线、已充满停充 | 4143 恒定 | **0 mA** | `0x000B`（CHG=1, FC=1） |
| **拔线瞬间** | 4085 | **−269 mA** | — |
| 插回、充电 IC 未起身 | 4128 | 0 mA | `0x0000` |
| 充电中 | 4195 | **+200 ~ +235 mA** | `0x000B` |

结论：**`Current(0x0C)` 本身是好的**，只是"充满停充"时它本来就该读 0。
真正能用的充电标志是 **`OperationStatus(0x3D)` 的 bit0 CHG**（BQ27xxx 标准位），
本机实测可用；`BatteryStatus` 的 DSG 位不可用，别再碰。

## 3. 现在的判据

按证据强弱排队，**没有证据就保持上一次状态，绝不凭空判"充电"**：

| 顺序 | 条件 | 强度 | 响应 |
|---|---|---|---|
| 1 | `ma > +40 mA` | 强 | 立即切"充电" |
| 2 | `ma < −40 mA` | 强 | 立即切"未充电" |
| 3 | `0x3D` bit0 `CHG=1` | 弱 | 连续 2 次（6 s）才认 |
| 4 | 24 s 抬压 ≥ 4 mV | 弱 | 连续 2 次（6 s）才认 |
| 5 | 以上都不满足 | — | **保持原状态** |

有两条刻意的取舍：

- **不用「电压下跌 → 判未充电」**。电池充满后电压本就在缓慢回落（实测 `d24` 常为
  −1 ~ −2 mV），拿它当证据会让光点一帧有一帧无。第一版实现里就有这条，
  抓帧抓到过一帧绿色（未充电色）夹在琥珀色中间，就是它干的。
- **弱证据要去抖**。充满停充时 CHG 位会短暂抖动，不滞回的话弧条会来回闪。

真机验证：

```
[BAT] valid=1 soc=30% mv=4149 ma=0 charging=1 op=0x000B d24=+0mV
[CHG] IDLE -> CHARGING  ma=0 mv=4147 d24=+0mV soc=30% op=0x000B
```

拔线 → 3 s 内 `charging=0`，弧条停摆；插回 → 约 15 s 后（等充电 IC 起身）恢复流水灯。

## 4. 模拟表盘补上充电流水灯

v3.1.1 之前，数字表盘 4 格有流水灯，**模拟表盘那条 6 格弧在充电时只是整排静态变琥珀**，
没有任何动画。现在两套表盘统一：

- 已充格 → 暗琥珀 `(146,110,46)`
- 未充格 → 暗板岩 `(46,54,64)`
- 跑动光点 → 亮琥珀 `(255,216,124)`，**径向额外外扩 1.6 px**，700 ms 前进一格
- 方向沿"电量增长方向"（这条弧是从右往左填，所以光点从右往左跑）

实现上把外沿判定拆成 `hotOut2` / `out2` 两级，只有光点那一格允许外扩，
其余格仍按原半径收紧，弧条粗细不会变形。

## 5. 新增串口命令

| 命令 | 作用 |
|---|---|
| `CHGH` | 回放近 2 分钟电池采样历史（40 条 × 3 s）：电压 / 电流 / SOC / 是否充电 |
| `BAT` | 输出增加 `dsg=` / `op=` / `d24=` 三个字段 |

## 6. 已知问题（本版未修）

屏上电量百分比**不准**：现在恒定显示 `30%`，但 4149 mV 对 500 mAh 单节锂电其实约 85%，
而且 `0x3D` 自己报 `FC=1`（已充满）。

根因和 `fcc=3000mAh`（实际 500 mAh）是同一件事：这颗 BQ27220 **从没写过电池配置**
（Design Capacity / chem ID / 校准），SOC 是它自己瞎算的。

充电判定可以绕过它（见上文），但**电量百分比绕不过**。修法是把 SOC 改成按电压查表估算，
或者给电量计写配置 —— 后者需要 UNSEAL 后写 Data Memory，有变砖风险，单独评估。
