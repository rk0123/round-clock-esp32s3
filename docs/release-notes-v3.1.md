# v3.1 发布说明

主题：**音量变成全局的（连小智）**、**外圈进度条可以拖**、**Wi-Fi 记住密码就直接连**。

> 本版同时包含 v3.0 / v3.0.1 之后尚未发布的 WorkBuddy 桌面伙伴相关修复。

## 1. 音量：一颗键管住所有声音，另外加了一键静音

**问题**：设置页的音量只作用在 `ESP32-audioI2S` 的软件音量上。小智语音不是走播放库的——
它是把 Opus 解出来的 PCM 直接 `i2s_channel_write` 到 I2S，**完全绕过软件音量**，
所以下拉菜单调到 0，小智照旧大声说话。

**改法**：把响度整体挪到硬件上。

- 播放库音量固定为满值 21（不再做软件衰减，避免与硬件音量叠加成双重衰减）。
- `VOL` 命令（下拉菜单 / 串口）现在把 0..21 线性映射成 0..100，写进 ES8311 的 DAC 音量。
  两条通路（库解码 / 小智直写）最后都会经过 DAC，因此一起受控。
- 音量行的两颗 `-`/`+` 中间新增一颗**静音键**（r11，喇叭图标）：点一下归零并记住原档位，
  再点还原；没记到档位就回 12/21，不会让人卡在无声里。静音态图标变红并压一条斜杠。

真机日志：

```
VOL 21 → [AUD] volume -> 21/21 (dac 100/100)
VOL 0  → [AUD] volume -> 0/21  (dac 0/100)
静音键 → [UI] MUTE volume=0/21   → 再点 → [UI] unmute volume=16/21
```

## 2. 音乐：外圈进度条可拖动

屏幕最外圈那道橙弧原来只是"看"的，现在能拖。

- 按住环带（半径 148–180）任意位置即进入拖动，弧变黄、末端跟一颗白色把手，
  副信息实时变成 `SEEK 03:28 / 04:20`；松手才真正跳转，并 toast 目标时间。
- 拖动期间刷新率从 120ms 提到 90ms（跟手），且拖动过程不产生 TAP/SWIPE——
  以前在边缘松手会被当成翻页手势，拖个进度条页面就跑走了。
- 跳转按「时长比例 × 文件字节数」换算（`setFilePos()` 吃的是字节偏移，不是秒），
  CBR 精确、VBR 近似。

**边界（必须说清）**：只有 **TF 卡本地文件**能真跳。音频库的 `setFilePos()` 硬性要求
`m_dataMode == AUDIO_LOCALFILE`；播客是网络 m4a 流，按时间跳转要重新解析 MP4 的 moov 索引，
库做不到。播客上拖环会提示「播客不支持跳转」，但仍然会吞掉这次手势，不会误翻页。
电台是直播流、没有时长，本来就不显示进度环。

真机日志：

```
SEEK 120   → [AUD] seek -> 120s/260s (4809334/10420224 bytes) OK → 5s 后 pos=126s
RINGDROP 800 → [UI] ring seek -> 800/1000 = 208s/261s → seek OK → pos=213s
播客 SEEK 600 → [AUD] seek -> 600s/3688s (...) REJECTED
```

## 3. Wi-Fi：记住的密码直接连，不再要求点确认

**问题**：点开一个 SSID，即使密码已经从密码簿里自动填好，仍要再点一次 `JOIN` 才连。
用户的理解是"我密码都记住了，凭什么还要我确认"。

**改法**：

- 点行主体：密码簿里有记录（或开放网络）→ **立即连接并重启进 STA**，不再进键盘页。
- 点行尾的「改」：才进键盘页改密码。这是必须留的出口——否则密码改过之后会陷入
  "点了就连、连不上只能再点、永远改不了密码"的死循环。
- 密码簿里没有的加密网络，仍然走原来的"输密码 → JOIN"。
- 开机 `WiFi.setAutoReconnect(true)` 无条件打开：配网页扫描时会临时关掉 STA 自动重连，
  若那时直接断电，开关会留在关闭态，这一行保证下次开机断线能自己回来。

列表页行尾的绿勾换成了蓝色「改」字，一眼能看出"这行是已记住的、点哪儿能改"。

## 4. 桌面伙伴（v3.0 起）

旧版拓麻歌子正式封存为 `firmware/pet_v29_sealed.h`（原样保留、不参与编译），宠物改成
参考 anthropics/claude-desktop-buddy 的七态形态：sleep / idle / busy / attention /
celebrate / dizzy / heart，五种 ASCII 精灵，状态由桌面桥接器推送而不是自己编。
屏显接入真实的「积分 / 连续天数 / 能量」，并用 `buddy-relay/` 一个部署在云上的
单端口中转 + WiFi 轮询，让设备不插电脑也能跟 WorkBuddy 同步（详见 README）。

**v3.1 修正的是这条链路里的两个硬伤**：
- `--replay` 读进来的审计事件会被下一轮的空列表覆盖，导致回放永远不生效 —— 已修。
- 设备 OK/NO 真落地改为 `--uia`：用 UI Automation 扫描 WorkBuddy 的控件树，
  **只在真的存在**「允许 / 同意 / 允许一次」这类按钮时才点，扫不到就什么都不做；
  **永不点「始终允许 / 永久允许」**（设备只能代表这一次）。
- 硬边界写进 README：`*.needs-approval` 事件的 `decision` 字段是 `info`，
  多数是事后审计通知，执行时并没有弹窗在等；只有 `sensitive-protection` 才真的等人确认。
