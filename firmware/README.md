# RoundClock 固件 · ESP32-S3-Touch-LCD-1.85B

圆形 360×360 桌面终端固件：**机械表盘 / 电子表盘 / 音乐播放 / 航班雷达 / 番茄钟 / 设置 / Wi-Fi 配网** 七页，
自绘 RGB565 帧缓冲（不用 LVGL）。已在实机验证，并**在真实 Wi-Fi 下跑通全部数据链路**；
配网可**完全在设备上完成，不需要手机或电脑**（设置 → Wi-Fi，见第 2 节）：

```
[NET]  wifi=OK ip=192.168.1.42
[TIME] SNTP -> 2026-11-15 17:06:45 wday=0
[WX]   open-meteo HTTP -1 -> METNO 17C 多云 12/19 sym=partlycloudy_night (39917 bytes)
[ADSB] HTTP 200 / read 23789 bytes / live=10 demo=0 total=10
[AUD]  TONE 440Hz -> connecttoFS OK / Channels:1 / SampleRate:44100 / decoding=YES
```

> **v0.21**：**Wi-Fi 排障通道 + 修掉自己打断握手的老 bug**。
> 起因是有一次整机连不上 AP，`STATUS` 只报一个 `OFFLINE`，天气/航班/电台全哑，看不出为什么。
> - ⭐ **`esp_wifi_scan_start()` 在 STA connecting/connected 时直接返回 `ESP_ERR_WIFI_STATE`**
>   （Arduino 层就是 `-2`）。原来只要后台在重连，`SCAN` 永远只能打出 `[SCAN] -2 networks`，
>   排障时等于瞎的。现在扫描前先 `disconnect(true)` 关射频 → `mode(STA)` 重开 → 等回 IDLE 再扫，
>   扫完自动恢复连接（`gNetHold` 期间后台重连暂停）。
> - ⭐ **老的重连逻辑自己把握手打断**：每 15 s 一次 `disconnect(false,false)` 紧接 `begin()`，
>   而一次 4-way handshake 还没走完就又被 begin，日志里反复出现
>   `E wifi: sta is connecting, return error`，于是永远停在 `204 HANDSHAKE_TIMEOUT`。
>   现在改成 30 s 间隔 + 彻底重置 STA（关射频 → 重开 → begin，中间各留 200/100 ms 退避）。
> - **`STATUS` 增加 `WiFi diag` / `WiFi ssid` 两行**：`status` / `lastReason` / 掉线次数 / 信道 / mode / SSID 长度。
>   `lastReason` 是挂 `ARDUINO_EVENT_WIFI_STA_DISCONNECTED` 事件存下来的真实 reason
>   （core 3.0.7 的 `WiFiClass` 只有「码→名字」的 `disconnectReasonName()`，取不到当前原因）。
> - 新增 **`WPASS`**：只报已存密码的长度 / 空格数 / 非可打印字符数，不打印明文。
> - `SCAN` 现在会把 NVS 里保存的那个 SSID 标出来，并打印它的 dBm / 信道 / `enc` 编码。

> **v0.20**：**时间真正不依赖网络** —— 板载 **PCF85063 RTC**（I²C `0x51`）已跑通，
> 并且顺手挖出两个**真根因**：
> - ⭐ **RTC 寄存器偏移是实测出来的，不是 0x02**：这颗器件的时间区在 **0x04..0x0A**
>   （0x04 秒 / 0x05 分 / 0x06 时 / 0x07 日 / 0x08 星期(掩码 `0x07`) / 0x09 月 / 0x0A 年），
>   照数据手册的 `0x02` 写会全部落进 RAM 区（0x02/0x03 可写但**永远不走时**，0x0B..0x0E 恒为 `0x80`）。
>   判据：往 0x04..0x0A 写 `55 58 23 15 00 11 26` 能原样读回；等 8 s 秒 `0x55→0x06` 且分 `0x58→0x59`（真实 1 Hz 进位）。
> - ⭐ **`Wire` 跨任务竞争**：触摸任务（Core1，100 Hz）和主循环共用一条 I²C 总线，Arduino 的 `TwoWire`
>   不是线程安全的 —— 两个任务同时 `beginTransmission` 会让事务互相插队，症状是「写进去了但少几字节 /
>   读回来字节错位 / 某个寄存器自己在按秒跳」。现已加**全局互斥 `I2C_Lock()/I2C_Unlock()`**，
>   触摸、BQ27220、RTC、ES8311 四处全部串行化。
>
> 时间优先级：**RTC（准）> NVS 最后一次已知时间 > 固件编译时刻**。
> ① 开机先读 RTC，合法就直接用（`[RTC] restored from PCF85063: ...`，`STATUS` 里 `boot=RTC` 可验）；
> ② 联网时 NTP 只做**校准**：连上即对一次，之后每 **3 h** 一次，对完立刻写回 RTC 并存 NVS；
> ③ 断网运行期间每 10 min 读一次 RTC，软时钟漂 ≥2 s 就按 RTC 纠正；
> ④ RTC 不可信（年份越界 / 没装备用电池）时退回 **NVS 里最后一次对好的时间**（`boot=NVS`），
>    最差也只是"停在关机那一刻"，不会像以前那样差几个月；
> ⑤ 新增串口 **`RTC`**（原始 7 字节 + 是否可用）、**`SETTIME 2026-11-15 23:30[:00]`**（无网手动设时，立即写 RTC）、
>    **`RTCD <reg> [len]` / `RTCW <reg> <b0> [b1..]`**（原始寄存器读写，十六进制，查芯片用）。
> ⚠️ **RTC 断电继续走要靠备用电池**：板上留有 RTC 电池接口。装了电池 → 断电也不停；

> （DNS + UDP）实测常要 1~3 s，首次几乎必失败，且失败后**永不重试**，时钟就一直走软时钟。

> （`getLocalTime` 在 NTP 未回包时会"成功"返回 1970，旧代码没判，会把 1970 当成已对时）。

> 而 `setAutoReconnect` 只管"曾经连上过又掉线"。换了路由器 / 开机时 AP 还没起来，
> 就永久离线。现在每 15 s 主动重新 `begin` 一次（日志 `[NET] wifi retry #N begin 'xxx'`）。
> ④ 没拿到真实数据时按 30 min / 60 s 的常规周期重试，太久。现在失败后 15 s / 20 s 就重试。
> ⑤ **`api.open-meteo.com` 在部分网络下整段不通**（详见第 4 节），加 MET Norway 做第二兜底。

## 1. 一键编译 / 烧录

工具链用 **Arduino IDE 内置的 arduino-cli + esp32 core 3.0.7（IDF 5.1）**。
不要用 PlatformIO 里那份 framework（实测是 Arduino 2.0.17 / IDF 4.4，缺 QSPI 字段，编不过）。

```bat
build.bat              :: 只编译
flash.bat              :: 编译 + 烧到 COM12
flash.bat COM5         :: 指定别的端口
```

FQBN：

```
esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,CDCOnBoot=cdc,CPUFreq=240,UploadSpeed=921600,PartitionScheme=app3M_fat9M_16MB
```

最终固件约 **1.81 MB**（app 分区 58%）、RAM 53 KB。串口是 **USB CDC**，波特率任意。

> `build.bat` / `flash.bat` 里用 `for %%I in ("%~dp0.") do set "SKETCH=%%~fI"` 把路径规范化：
> `%~dp0` 带尾部反斜杠，直接加引号会转义引号，arduino-cli 会报 `sketch path is not valid`。
> .bat 里请保持纯 ASCII 注释，中文在 GBK 代码页下会把命令行打散。

## 2. 配网（三种方式，都不用重编译）

### 方式 A：设备端配网页（推荐，真正脱离手机/电脑）

**任意页面从屏幕上半部往下长拉**（起点 y≤125、下拉 ≥55px）→ 进入设置页 → 点第一行 `WIFI` 进入配网页。
v0.15 起表盘上不再有齿轮图标，串口 `SETTINGS` 也能直接打开设置页：

1. 自动**异步**扫描周边 2.4G 网络，列出 SSID / 信号格 / 锁标（加密）；**已记住密码的网络行尾带绿勾**
2. 点一个网络 → 进入键盘态：顶部显示 SSID，下方是**屏上 QWERTY 键盘**
   - **密码输过一次就记住**（NVS 密码簿，最多 5 个网络）：再点同名 SSID 密码已自动填好，
     只显示 `PASS SAVED / TAP JOIN`，点一下 `JOIN` 就连；想改密码直接退格重打即可
   - 字母 / 数字符号（`SYM` 切换）/ 大小写（`CAPS`，密码区分大小写）/ 退格 / 空格 / `CANCEL` 返回
   - 密码框只显示最后一位明文、其余打码（`*`）
3. 点 `JOIN` → 写入 NVS 并**重启**，重启后自动 STA 联网，天气 / 航班 / 电台切真实数据
4. 列表态可上滑 / 下滑滚动；底部两个按钮 **`< BACK`（回设置页）/ `RESCAN`（重扫）**

> 键盘是纯触摸点按；圆屏安全区（r≤158）限制下，键盘压在屏幕中段，已实测最外角落在 r≤158 安全区内。
> **返回键放底部**：v0.10 之前画在左上角 (45,39)，那里距圆心 ≈195 px 已出圆屏，被外壳挡住根本按不到
> （"Wi-Fi 页回不去"就是这么来的）。现在底部两键四角最远 r≈155，压进安全区。
> 列表态滑动只用于滚动网络、不会翻页。
> 超长 SSID 按**像素宽度**截断（`textWidth()` 实测，超出补 `..`），不会顶出行右边界。
> 网络名/密码里的字符必须在本机字库内（基础 ASCII）才能显示，生僻字符会显示为空白。
> 连不上网时 STA 会一直后台重连，而 **ESP-IDF 在 STA connecting/connected 状态下
> `esp_wifi_scan_start()` 直接返回 `ESP_ERR_WIFI_STATE`**（Arduino 层翻译成 `-2`），
> 所以只要后台在重连，扫描就永远拿不到结果，页面卡 `SCANNING...`。
> v0.21 起扫描前先 `disconnect(true)` 关射频 → `mode(STA)` 重开 → 等回 IDLE 再扫，扫完自动恢复连接。

### 方式 B：配网 AP（手机/电脑网页，可选）

串口发 `AP` 手动打开 AP `RoundClock-Setup`，手机/电脑连上后浏览器打开
`http://192.168.4.1/` 选 Wi-Fi、填密码（彩云 Token 可留空），提交后写 NVS 并重启。

> **注意**：v0.7 起，刷机后**不再自动开 AP**（避免依赖手机/电脑）。设备改为离线跑演示数据，
> 用户随时从 设置 → `WIFI` 行本机配网；只有想用手机配网时才主动发 `AP` 命令。

| `WDAY <0..6>` | 强制星期（0=周日..6=周六），用于验收星期窗显示 |
| `RTC` | 打印 PCF85063 `0x04..0x0A` 原始 7 字节 + 解出的时间 + 是否可信 |
| `SETTIME 2026-11-15 23:30[:00]` | 无网络时手动设时，排队写进 RTC 并落 NVS |
| `RTCD <reg> [len]` / `RTCW <reg> <b0> [b1..]` | 原始寄存器读/写（十六进制），定位芯片寄存器映射用；写后自动回读 |

配置存在 NVS（`Preferences`，namespace `rcfg`），**优先于 `config.h`**。亮度/音量也在同一命名空间（`bright` / `vol`）。

### 连不上网怎么查（v0.21 加的排障通道）

`STATUS` 现在会多打两行：

```
WiFi      : OFFLINE  ip=-  rssi=0 dBm
WiFi diag : status=5 lastReason=204(HANDSHAKE_TIMEOUT) drops=4 ch=8 mode=1
WiFi ssid : 'HomeWiFi' saved, 10 chars pass
```

`lastReason` 是挂 `ARDUINO_EVENT_WIFI_STA_DISCONNECTED` 事件记下来的真实断开原因
（core 3.0.7 的 `WiFiClass` 只有「码 → 名字」的 `disconnectReasonName()`，取不到当前原因，
所以只能自己存快照）：

| reason | 含义 | 该查什么 |
|---|---|---|
| **201 NO_AP_FOUND** | 扫不到这个 SSID | 2.4G 没开 / 名字改了 / 隐藏且未指明 / 距离太远 |
| **204 HANDSHAKE_TIMEOUT** | 扫到了、4-way 握手超时 | **99% 是密码错**；其次 MAC 过滤、要求 802.11w PMF |
| **15 4WAY_HANDSHAKE** | 握手阶段被拒 | 密码错 / 加密方式不兼容 |
| **200 BEACON_TIMEOUT** | 连上后又丢信标 | 信号太差 / 路由器踢掉 |

`SCAN` 会直接把保存的那个 SSID 标出来，并打印它的 dBm / 信道 / `enc` 编码：

```
[SCAN] 6 networks (status=6 lastReason=8 ASSOC_LEAVE)
   1  HomeWiFi    -62 dBm  ch 8  SECURED  <== SAVED SSID
[SCAN] saved 'HomeWiFi' found: -62 dBm ch8 enc=4 (0=OPEN 2=WEP 3=WPA_PSK 4=WPA2_PSK 5=WPA_WPA2 6=ENT 7=WPA3 8=WPA2_WPA3)
```

`enc=4` 是 WPA2-PSK，ESP32-S3 完全支持；如果这里是 `7`（WPA3-only）才需要另想办法。
`WPASS` 再确认 NVS 里那串密码没被屏幕键盘输坏（全角、尾随空格、被截断）：

```
[WPASS] ssid='HomeWiFi' len=11 | pass len=10 spaces=0 nonprint=0 nonascii=0
```

三个都对上（SSID 能扫到、enc 不是 WPA3、密码格式合法）还连不上，那就是密码内容本身不对，
用 `WIFI <ssid> <pass>` 或设置页重新输一遍。

> **实案（2026-11-16）**：整机离线，`STATUS` 只有 `OFFLINE`；查出 `lastReason=204`，
> 扫到 `HomeWiFi` -62dBm ch8 `enc=4`，`WPASS` 报 10 位纯 ASCII —— 全部"正常"。
> 最后是**密码内容错**：新旧密码**长度都是 10 位**，所以长度这关根本筛不出来。
> 换上正确密码后立即 `wifi UP 192.168.1.42`，航班 10 架、天气 `OPENMETEO live=1`、电台 `PLAYING`。
> 教训：`WPASS` 只能排除"输坏/截断"，**判断不了内容对不对**，最终只能靠真连一次。


> 彩云官方 demo token 实测返回 `429 API quota is exhausted`，必须用自己的 token。
> **但即使完全不填 token，天气也是真实的**：固件自动回落到 Open-Meteo（免密钥、约 550 B）。
> **v0.16**：完整链路是 彩云 → Open-Meteo → MET Norway → `DEMO`，只有三条全失败才标 `DEMO`；
> 状态栏始终写 `WX / 源名 / LIVE|DEMO`，点天气区会立刻重拉真实天气（旧的「循环切 7 条假天气」已删除）。

### 锁屏息屏与唤醒亮屏（v0.17：只按键，触摸不唤醒）

**v0.15 起屏幕上的虚拟锁键已彻底删除**（连同 `drawLockIcon()` 与热区），表盘不再有按钮；
息屏统一用**右上实体 BOOT 键（GPIO0）** —— 按一下息屏，再按一下亮屏。
历史上 v0.10~v0.14 曾是「实体键 + 屏幕锁键」双通道，现在只留实体键。

- 板上只有两个实体键：**BOOT（GPIO0，可编程，按下拉低）** 和 **PWR（硬件电源锁存，官方明确"不支持自定义"）**。
  PWR 是长按 2 s 关机 / 短按 1 s 开机的硬开关，软件读不到它，别指望它做息屏。
- `pollButton()` 在 `loop()` 里轮询 GPIO0，**25 ms 消抖 + 只认按下沿**（长按不连发，松手无动作）。
- 开机时**按住** BOOT 仍会进下载模式，这是芯片 strapping 行为，无法也不该改；正常上电后按它是普通按键。
- 实测 USB 侧 DTR/RTS 四种组合都不会把 GPIO0 拉低，**插电脑不会误锁屏**（`STATUS` 里 `Button: GPIO0=1`）。
- 串口 `BTN` 可注入一次按键（走同一个 `toggleLockScreen()`），无手指也能验收。

- **息屏**：先把帧缓冲整屏刷黑再 `Set_Backlight(0)`，屏幕完全黑掉（不是只调暗），同时不跑动画。
- **亮屏**：恢复到你设置的亮度、重绘当前页，并弹一句 `UNLOCKED`。
- **v0.17：息屏后触摸一律忽略，只认实体 BOOT 键唤醒** —— 旧版任意触摸就亮屏，放口袋里蹭一下就唤醒，
  非常容易误触。现在 `pollTouch()` 在 `gLocked` 时直接丢弃触摸事件；串口 `TAP` 注入同样不唤醒，
  要无手指验收唤醒请用 `BTN` 或 `LOCK`。
- **锁屏不影响播放**：锁屏只关背光，音频跑在 Core0 的独立 `audioTask` 上，电台 / MUSIC(TF) / 播客
  在息屏后继续播；`LOCK` 日志会打印 `audio=still playing`。
- 串口 `LOCK` 切换同一状态；`TAP <x> <y>` 注入一次点击，走**和真手指完全相同的命中判定**。

### 触摸手势（v0.8 重做，解决"滑动不大灵"）

旧实现有两个硬伤：① 依赖 CST816S 芯片内置手势引擎，对轻扫不敏感；
② 只在中断里读一帧、采样率跟着 UI 重绘走（表盘 4 fps），一次快速滑动可能整帧被漏掉。
另外 `CST816_AutoSleep()` 里寄存器被写成了固定值 `10`（应为 `0x01`），**自动休眠根本没关掉**，芯片睡觉时坐标断续上报。

现在的做法：

1. `CST816_AutoSleep(false)` → 写 `0xFE = 0x01`（DisAutoSleep），并回读校验：`[TOUCH] DisAutoSleep(0xFE) <= 0x01 readback=0x01`。
2. 独立任务 `touchTask`（Core 1，priority 3）**100 Hz** 直接读 `0x01..0x06` 原始帧（GestureID / FingerNum / X / Y），
   完全绕开芯片手势引擎，也不再受重绘帧率影响。
3. 抬手时自己算位移：主方向 ≥ `26 px` 判为滑动（慢拖 1.4 s 内都算），总位移 ≤ `18 px` 且 ≤ `600 ms` 判为点击。
4. 判定结果丢进 8 深度的队列，`pollTouch()` 在主循环里取出分发（点击 / 翻页 / 列表滚动）。
5. I²C 读失败**不当成抬手**（否则一次总线抖动会把滑动误判成点击），跳过该帧重试。

阈值都在 `main.cpp` 顶部 `TOUCH_SWIPE_PX / TOUCH_TAP_PX / TOUCH_SWIPE_MS / TOUCH_TAP_MS`，觉得还钝就继续调小。

大时间用 44×64 的 4-bit 抗锯齿字库，冒号的**墨迹中心精确落在 x=180**
（真机截图实测 180.35 / 180.43 px），不再有 1-bit 点阵放大 3 倍的 3 px 台阶。

## 4. 数据链路（已在板上验证）

| 链路 | 实现 | 刷新 |
|---|---|---|
| 时间（主） | **板载 PCF85063 RTC**（I²C `0x51`），开机即读，断网也准 | 每 10 min 读一次校正软时钟漂移（≥2 s 才动手） |
| 时间（校准） | SNTP（`ntp.aliyun.com` 为主，`pool.ntp.org` / `time.windows.com` 兜底） | 联网即对一次，之后 **3 h** 一次；成功即写回 RTC |
| 时间（兜底） | 固件编译时刻 `__DATE__/__TIME__` | 仅在「RTC 无应答 / OS 停振 / 无网络」时使用 |
| 位置 | `config.h` 的 `CITIES[20]`（中文名 + 经纬度），运行时 `gHomeLat/gHomeLon`，选中城市写 NVS `rcfg/city` | 换城市立即重拉天气 + ADS-B |
| 电池 | **BQ27220 电量计**（共享 I²C 0x55）：`0x2C` SOC / `0x08` 电压 / `0x0C` 电流 / `0x3D` OperationStatus | 3 s（与 100 Hz 触摸采样同任务串行读，避免 I²C 并发） |
| 充电判定 | 电流符号为准：`>+40 mA` 充电、`<-40 mA` 未充电（**立即**切换）；电流停在 0（充满停充）时看 `0x3D` 的 CHG 位或 24 s 抬压 ≥4 mV，需连续 2 次（6 s）才认 | 3 s |
| 天气主源 | 彩云天气 `v2.6/{token}/{lon},{lat}/weather` | 30 min |
| 天气兜底 1 | **Open-Meteo** `current=temperature_2m,weather_code` + `daily` 高低温，WMO code 映射中文 | 主源失败即启用 |
| 天气兜底 2 | **MET Norway** `locationforecast/2.0/compact?lat&lon`，英文 `symbol_code` 映射中文 | 前两个都失败时；都没拿到则 15 s 重试 |
| 航班 | `api.adsb.lol/v2/point/{lat}/{lon}/{nm}`，流式读到 64 KB 上限后解析 | 60 s；没拿到真实目标则 20 s 重试 |
| 电台 | **12 条**实测 200 / `audio/mpeg` 的 HTTPS MP3 直播直链（国内蜻蜓 CDN ×6、RFI 华语 / BBC / NPO / KQED / SomaFM ×6） | 长连接 |
| 音频解码 | `ESP32-audioI2S 3.4.0 → I2S → ES8311 → PA(GPIO9) → 喇叭` | 独立 `audioTask`（Core 0）持续喂 |

**为什么要有第三条天气兜底**：`api.open-meteo.com` 在部分网络下**整段不通**——实测同一时刻
PC 直连 `51.81.167.44` / `188.40.99.226` 两个解析结果都 15 s 超时（换 8.8.8.8 / 223.5.5.5 /
1.1.1.1 查 DNS 结果一样，排除 DNS 污染），而 `api.adsb.lol` 2.4 s 正常返回。
所以不是"国外站全被墙"，是这个域名在那个网络里不可达。
换成 MET Norway 后同一网络 1.8 s 返回，`[WX] METNO 17C 多云 12/19 sym=partlycloudy_night`。
它用英文 `symbol_code`（`clearsky_day` / `partlycloudy_night` / `rain` …），
映射中文不涉及 GBK，比国内那些返回 GBK HTML 的源干净。**注意它硬性要求带 User-Agent，不设会 403。**

**收音机卡死已修复**：早期 `connecttohost` / `loop()` 在 UI 主循环里同步跑，点播放时
DNS+TLS 握手要数秒、流卡顿会让 `loop()` 长时间阻塞 → 整个界面卡死（触摸/重绘全停）。
现在音频整体搬进独立的 FreeRTOS 任务 `audioTask`（Core 0），UI 只发"请求"
（`volatile gAudioReq`），由音频任务真正 `connecttohost` / `loop()`，UI 永不被阻塞。
并引入 `AudioState` 状态机（IDLE / CONNECTING / PLAYING / PAUSED / ERROR）+ 连接超时
（`setConnectionTimeout(3000,2000)`），连不上就显示 `ERROR` 而非无限转圈。
实测 `PLAY` 后状态 `IDLE → PLAYING running=YES`、uptime 持续增长、`reset=0`，
`STOP` 正常回到 IDLE —— 收音机页不再死机。

**航班距离换算有个已修的坑**：经纬度差乘 111320 / 110540 得到的是**米**，
必须 `/1000` 才是公里。旧版漏了，距离放大 1000 倍导致所有飞机被 `r>1` 过滤，
出现「HTTP 200 / 27 KB 却 live=0」。`tools/test_adsb_parse.py` 是这条的回归测试：
修复后 10 架、旧公式 0 架。

**真实数据不会被假目标悄悄替换**：只要成功解析过一次实时目标，就保存快照；
后续刷新失败或解析出 0 架时恢复快照并标 `STALE`（黄色 + 标题 `!`）；
**v0.16 起从没联网成功过就显示空雷达 + `NO SIGNAL`，不再补演示目标**。
切半径时按 `r *= oldRadius/newRadius` 重投影，不清空数据。

首次联网冷启动 TLS 偶发 `HTTP -11`，启动阶段会重试最多 3 次，超时放宽到 15 s。

### 5.1 "有点声音马上就没有了" —— 真正的根因

排查过程中一共剥出六层，前五层只是让症状变形，**最后一层才是真因**：

1. `netTask` 原钉在 Core0，和库内解码任务抢 lwIP/TLS 锁 → 移到 Core1。
2. `Audio` 对象原在 `setup()`（Core1 的 loopTask）里 `new`，I2S/GDMA 中断注册到 Core1，
   播放时抢占 QSPI 刷屏，在 `spi_master.c:setup_priv_desc` 触发 `StoreProhibited` 整机重启
   → 改在 `audioTask()`（Core0）里 `new Audio()`。
3. `setConnectionTimeout(3000,2000)` 同时作用于 `WiFiClientSecure` 的 connect **和 read**，
   直播流一次 chunk 间隔 >2 s 就被误判断连 → 放宽到 `(8000, 8000)`。
4. 喂流任务优先级一度提到 3，压过库内解码任务(2)，`i2s_channel_write(50ms)` 反复超时，
   库把 `m_validSamples` 永久卡住 → 喂流降回 **1 < 解码 2**（库作者的设计）。
5. `audStart()` 里曾多做一次 `setPinout()` 想"重启 I2S"，反而让
   `zeroI2Sbuff() → i2s_channel_preload_data()` 在已 disable 的通道上写空 DMA 描述符，
   Core0 panic（backtrace：`i2s_channel_preload_data → Audio::zeroI2Sbuff → Audio::setPinout`）→ 删掉。
6. **真因**：库 3.4.0 的 `Audio::zeroI2Sbuff()` 在每次 `i2s_channel_enable()` 前用
   `i2s_channel_preload_data(tx, 2字节)` 试图"清零 DMA 缓冲"。在 **IDF 5.1 / esp32 core 3.0.7**
   下这会把 GDMA 描述符链留成一次性状态：前 **40~57 KB** 正常吐出（就是听到的那一小声），
   之后每条 `i2s_channel_write()` 都返回 `ESP_ERR_TIMEOUT` 且 `i2s_bytesConsumed == 0`，
   解码仍在跑、InBuffer 一路涨到 655350 顶格，但喇叭再也不响。
   → **把这 2 字节 preload 整个去掉**，只保留 `i2s_channel_enable()`。

诊断靠加在库里的 `gI2sDiag[10]` 客观探针（写次数 / 超时 / 0 字节写 / 累计字节 / 采样数 /
`init` `reconfig_gpio` `preload` `enable` 四步 `esp_err_t`），`AUD` 命令会打印。
补丁前 `bytes` 钉死在 `57342`、`to/zero` 随写次数线性增长；补丁后 `to=0 zero=0`、
`bytes` 每 10 秒涨约 2 MB。

> 外部库不在工程目录里，**换电脑/重装库后必须重新打补丁**：
> `patches/ESP32-audioI2S-3.4.0-roundclock.patch`（对 `Audio.cpp` 的 8 处 hunk）。
> 原始备份 `Audio.cpp.roundclock.bak` 与库放在一起。打了补丁后
> `audio_player.h` 才能链到 `gI2sDiag[10]`。

### 5.3 v0.15 加固：暂停重复音 / 播客卡住 / 快速切台

**① 按暂停后一直重复同一个音（很难受）**

排查 v0.14 时为了试"是不是 `auto_clear` 导致描述符不回收"，把
`m_i2s_chan_cfg.auto_clear` 从 `true` 改成了 `false`，后来证明真因是 preload，却忘了改回。
`pauseResume()` 只把 `m_f_running` 置 false 并清空**软件**缓冲，GDMA 描述符里最后那一小段
音频仍被 I2S 反复发送 —— 于是暂停后循环同一个音。

修复两处（双保险）：

- 库里 `auto_clear` **改回 `true`**：TX FIFO 空时 IDF 自动发零而不是重放最后一段。
- 固件 `audioTask` 主循环按状态统一同步数字增益：
  `A_PAUSED / A_IDLE / A_ERROR → setVolume(0)`，恢复时还原用户音量 `gAudioVol`。
  集中在这里做，`TOGGLE / STOP / SOURCE / VOL` 各条命令路径都不会漏。

`AUD` 新增 `gain=<实际库音量> mute=YES/NO`。实机：播放 `gain=16 mute=NO`；
暂停 4 s 后 `gain=0 mute=YES` 且 `i2sdiag w=339 bytes=1562112` **完全冻结**；
恢复后 `gain=16` 且 `w=624 bytes=2875392` 继续涨。全程 `to=0 zero=0`，
证明改回 `auto_clear=true` 没有让 v0.14 的 GDMA 修复回归。

**② 播客经常卡住**（四个叠加原因）

| 原因 | 修复 |
|---|---|
| 连接宽限固定 15 s，但 `swap.fm → prfx.byspotify → play.podtrac → simplecastaudio → hash_redirect` 4 层重定向每层都要重新 TLS 握手（0.8~5 s），于是在**连接阶段**不停 `stopSong → 重连 → 再等 30 s` | 连接宽限按音源区分：电台 15 s、**播客 45 s**；播客 socket 超时 `(15000,15000)` |
| `!running` 一律当"播完"，`audNext(1)` 直接跳下一集；重定向期间 `isRunning()` 会短暂为 false，于是「点播放 → 立刻跳 EP02 → 又连接 → 又跳」 | 新增 `gAudStartI2s`：**本次必须真往 I2S 吐过 >4 KB** 才允许自动下一首；否则耐心等，超过宽限才重连 |
| 断流判据只看 `inBufferFilled()` 是否变化；播客是固定大文件，下载完后 buf 只减不增，慢 CDN 下被误判断流 | 改为「InBuffer 变化 **或** `gI2sDiag[3]` 真实输出字节增长」都算活着；播客 stall 宽限 25 s |
| RSS 里的直链带 3 层统计跳转，且先按 384 字节截断再解析，长 query 被切断 | `podNormalizeUrl()` 按 `/` 分段找第一个非跟踪域名，一次压成 `https://npr.simplecastaudio.com/...`；解析时先用 640 B 缓冲接完整 URL、规范化后再存入曲目表；`podLoad()` 对旧 NVS 记录同样规范化 |

另外播客重连上限从 6 次降到 3 次，仍失败就**跳下一集**，不再把用户钉在同一条坏链上。

实机（重抓 feed）：`feed read 66084 bytes in 1393 ms -> 7 episodes`，POD 列表 URL 全部是
`https://npr.simplecastaudio.com/...`；`SRC 2 + PLAY` 只剩 1 次 `hash_redirect`、
`SSL 2562 ms`，12 s 内 `pos=3s/2273s running=YES`、`idx` 保持 `1/7` 不跳集、`to=0 zero=0`。

**③ 快速连按切台 `FAILED`**：上一条 HTTPS socket / lwIP PCB 还没释放，
`connecttohost()` 直接返回 false（实测 `TRACK 8 → TRACK 1` 必现）。
`audStart()` 在 `stopSong()` 后加 60 ms 释放窗口，失败再等 180 ms 重试一次。
实测 `TRACK 8(BBC) → TRACK 1(QTFM)` 成功，`state=PLAYING gain=16 mute=NO`。

### 5.4 能不能连蓝牙耳机？——**不能，这是芯片级限制**（2026-11-15 结论）

> 结论先说：**ESP32-S3 没有经典蓝牙，A2DP 在硬件层面就不存在**。
> 任何库、任何固件都绕不过，别在这上面花时间（本项目已确认放弃）。

| 事实 | 依据 |
|---|---|
| ESP32-S3 只有 **BLE 5.0**，无 BR/EDR（经典蓝牙） | 官方 ESP-IDF 文档：*"ESP-Bluedroid for ESP32-S3 supports **Bluetooth LE only**. **Classic Bluetooth is not supported**."*；芯片手册「蓝牙：低功耗蓝牙 (Bluetooth LE)：Bluetooth 5、Bluetooth Mesh」 |
| 蓝牙耳机的音乐传输是 **A2DP，属经典蓝牙 profile** | `ESP32-A2DP` 库只支持**老 ESP32**（经典蓝牙版），FQBN 换到 `esp32s3` 直接编译失败 |
| LE Audio / LC3 也不行 | 需要 BLE 5.2 的 **ISO 等时通道**，S3 是 5.0 没有；ESP-IDF 也不提供 LE Audio 主机侧；且绝大多数在售耳机只支持 A2DP |
| 板上没有 3.5 mm 耳机孔 | 只有**扬声器焊盘** + ES8311 + 功放使能 `GPIO9`（`PA_EN`） |

**将来若一定要「戴耳机听」，只有两条真能走的路（本项目暂不实装）：**

**路线 A：外挂 I2S → A2DP 发射模块**（BK3266 / CSR8675 / QCC3008 类小板，约 20~50 元）

```
模块 DIN   ←  GPIO47 (I2S DOUT，与 ES8311 并联，数据同源)
模块 BCLK  ←  GPIO48
模块 LRCK  ←  GPIO38
模块 3V3/GND ← J6 口（GPIO7/GPIO8 那个 4pin 座）
模块 PAIR  ←  GPIO7   （拉低 2s = 进配对/断开）
模块 STATUS→  GPIO8   （读高/低 = 耳机是否已连上）
```
固件侧要改的：设置页加 `OUTPUT  扬声器 / 蓝牙`；选蓝牙时 `digitalWrite(PA_EN, 0)` +
`es8311_set_voice_volume(0)`（板载喇叭彻底哑，但 **I2S 不能停**，模块还要吃数据）；
`GPIO7` 做配对触发，`GPIO8` 做连接状态显示（已连接 / 未连接 / 配对中）。
**做不到**：扫描并列出周边设备让你点选——配对与设备列表都在模块内部，ESP32 拿不到。

**路线 B：焊 3.5 mm 耳机座**（2 元，需动烙铁）

从 ES8311 的 DAC 输出并到耳机座，耳机座的**机械检测脚**接去控制 `PA_EN`：
插耳机 → 功放断电（外放哑，耳机响）；拔掉 → 恢复外放。固件只需承认这个"硬切换"，
若要显示状态就把检测脚也引到一个空闲 GPIO（J6 的 GPIO7/8）。优点是零延迟、不用配对、音质更好。

## 9. 已知限制（诚实清单）

- **不支持蓝牙耳机（芯片级限制，不是没写）**：ESP32-S3 只有 BLE 5.0，**没有经典蓝牙**，
  A2DP 无法实现；LE Audio 也因缺 ISO 通道 + ESP-IDF 无主机侧支持而行不通；
  板上也没有 3.5 mm 耳机孔，只有扬声器焊盘 + `PA_EN(GPIO9)`。详见 **§5.4**，
  里面有两条将来可选的硬件路线（I2S 蓝牙发射模块 / 焊耳机座）及各自固件改动点。
- **音频三音源已实装但仍有边界**：TF 卡递归 2 层子目录、**最多 20 首**（更深目录不扫）；
  播客只取 RSS 前 130 KB / 前 8 个 `<enclosure>`（实测 NPR feed 拿到 7 集），不支持分集分页与非 ASCII 剧集名；
  无 SD 卡热插拔检测，插卡后要 `TFSCAN`。v0.15 已把 podtrac / swap.fm 跟踪跳转压成 CDN 直链，
  但最后一层 `hash_redirect` 仍由 CDN 决定，对方改域名或加证书链时可能失败。
- **时间已不依赖网络（v0.20）**：板载 PCF85063 负责走时，开机先读它（`STATUS` 里 `boot=RTC`），断网开机也准；
  SNTP 降级为"联网时每 3 h 校准一次并写回 RTC"，软时钟每 10 min 接受 RTC 纠偏。
  装了**RTC 备用电池**时断电也不停；没装电池则断电归零，此时退回 **NVS 里最后一次对好的时间**
  （`boot=NVS`，误差 = 关机时长），联网后自动校正 —— 只有 NVS 也空（首次烧录 / `CLEAR`）才用固件编译时刻。
  PCF85063 无温度补偿，典型漂移 ±1~3 分钟/月，靠 3 h 一次的 NTP 抹平。
- **自动熄屏 / 抬腕唤醒未做**：已加**手动息屏**（右上实体 BOOT 键任意页可用，v0.15 起屏幕上不再有锁键；真关背光到 0，**v0.17 起只按键唤醒、触摸不唤醒**）与亮度调节（10–100%，存 NVS），但无环境光/加速度传感器触发的自动熄屏。
- **没有 OTA**：固件更新仍需 USB 烧录（配置本身已可网页 / 串口 / 本机页面改）。
- 电台真实"可听"需人工确认：v0.14 / v0.15 已用客观指标证明 I2S DMA 持续输出
  （`to=0 zero=0`、`bytes` 每 10 秒涨约 2 MB、约 45 帧/秒实时速度、90 s 无重启；
  暂停时 `gain=0 mute=YES` 且字节数冻结），但本环境无法代替人耳确认音质与音量。
- 彩云天气需自带 token；不填时依次走 Open-Meteo → MET Norway，界面状态栏显示实际来源
  （`CAIYUN` / `OPENMETEO` / `METNO`）。三条都失败才退回 `DEMO`。

## 10. v2.x 结构变更摘要（本节之后的内容取代前面部分描述）

前面的章节写到 v0.27，那时的形态是「七页环形翻页 + 十字手势」。v2.0 做了大改，这里只记录**结论**，
细节见 [`../docs/firmware-integration.md`](../docs/firmware-integration.md) 与顶层 README。

### 10.1 导航从"七页环"改成"三层"

```
表盘  ←──→  应用中心  ←──→  某个应用
 ↑                                │
 └──────── 任意应用上滑回表盘 ────┘
```

- `PAGE_RING` / `ringStep` / 十字翻页全部删除，`navigate(dir)` 只剩下三条规则。
- `P_APPS = 7` 的应用中心是 **10 格正三角形**（1+2+3+4），设置坐顶点；`APP_GLYPH[]` 把格位与图标解耦，
  `-1` 是预留位（虚线环 r28 + 淡十字）。
- 表盘变成一块页两种脸（`gFace`，NVS `rcfg/face`）：点轴心 r≤34 或上滑换脸，左右滑进应用中心。
- 页面编号 `P_APPS=7 … P_TODO=13`，串口 `PAGE n` 语义不变。

### 10.3 内存必须重排

三张曲库表（`gRadio/gTf/gPod`，各 40×448 B）原来在 `.bss`，合计 52.5 KB 内部 RAM。
小智会话要同时吃 TLS（两块 16 KB 连续堆）+ ES7210 RX DMA 环，一开就爆，LCD 直接
`spi transmit (queue) color failed`。v2.7 改为 `ps_malloc` 上 PSRAM：

**内部静态内存 131,208 B → 77,472 B**，空闲内部堆从 77 KB 回到 148 KB，会话中仍有 80 KB 余量。

同时 RX 的 DMA 从默认 6×240 帧降到 4×160 帧（≈2.5 KB，省 3 KB）；
触摸与采音任务栈压到 4 KB（它们都不碰 TLS）。

### 10.4 采样率被播放侧锁死

ES8311 与 ES7210 共用 BCLK/LRCK，所以 **I²S 全局只能有一个采样率，选 48 kHz**：

- 录音：48 k 收 → 3 点均值降采样 → 16 k（`48000/3 = 16000` 精确整除）
- 小智上行：16 k Opus，60 ms 一帧（960 样本）
- 小智下行：24 k Opus → 线插值 ×2 → 48 k
- **TX/RX 都是 16 bit 立体声**，单声道数据必须左右各写一份，否则音调掉八度
